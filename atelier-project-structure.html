Le calcul Green API et le scan Creedengo sont indépendants ; les deux alimentent les mêmes rapports JSON.

Creedengo — À quoi ça sert ?

Analyse du code

Détecte les anti-patterns d'éco-conception dans le code source Java, Python et C#

Règles de la GCI

Identifie les requêtes SQL inutiles, les appels en boucle, les ressources mal libérées et autres coûts évitables

Et dans ce repo ?

SonarQube + plugin Creedengo, lancé avec --creedengo ou creedengo-analyzer.sh

Résultat

Score /100, grade, règles violées et rapport

scripts/start.sh — Piloter une analyse

Le script orchestre une analyse Green API de bout en bout : il prépare la cible, lance éventuellement l'application, exécute les contrôles et produit le dashboard et les rapports

Cibles & spécifications

Paramètres pour indiquer une ou plusieurs API, leurs contrats OpenAPI et, si nécessaire, un accès authentifié

Source & exécution

Paramètres pour choisir le stack, fournir le code source, démarrer l'API localement et activer les traces de diagnostic

Qualité du code & architecture

Options pour lancer Creedengo et contrôler les ADR, y compris depuis un dépôt Git ou un sous-répertoire

Score & intégrations

Paramètres de contexte pour le scoring, la proximité géographique, l'empreinte cloud et l'envoi vers SobriIT

Les valeurs peuvent venir des options CLI ou de variables d'environnement, selon le paramètre. Exemple : bash scripts/start.sh --stack java --build-and-run --source-dir ./my-app --creedengo

Partie 2 : Pour les plus rapides 🚀

Intégration d'une pipeline Green API dans votre projet

pr-green-api-axa.yml — Pipeline Green API

  • Trigger : PR + Scheduled (weekly dimanche)
  • Setup : JDK 17, Maven, Python
  • Clone analyzer : Récupère le repo analyzer
  • Exécute : scripts/start.sh avec paramètres
  • Analyse : Creedengo, Green Score, OpenAPI
  • Variables : Targets, Swagger URLs, Stack (auto/java/dotnet)

Recommandations pour intégrer la pipeline

Préparation des variables

Renseigner les targets, l'URL du Swagger, le stack, le profil d'exécution, les options de build, etc

TARGETS · SWAGGER_URL · STACK · BUILD_AND_RUN

Swagger accessible

Vérifier que le chemin est accessible depuis l'agent CI : authentification et réponse HTTP 200

/swagger · /v3/api-docs

Nom des modules

Contrôler les noms des modules Maven ou Gradle et cibler le bon sous-répertoire avant de la pipeline

Renseignement des secrets

Stocker les tokens et identifiants dans les variables secrètes de la CI, jamais dans le YAML ni les logs

API_TOKEN · CLIENT_SECRET · etc

API Green Score — Rappel des règles

Performance

Pagination (DE11), Filtering (DE08), Compression (DE01)

Caching

ETag/304 (DE02/DE03), Delta queries (DE06)

Scalabilité

Range/206 (Partial Content), Binary formats (Protobuf)

Architecture

Event-driven (AR01), Runtime Proximity (AR02), Single API (AR03)

Cloud & Observabilité

Scalable Infra (AR04), Cloud Footprint (AR05), Health/Metrics (LO01)

Comment le rapport est généré

flowchart LR
    A[API en fonctionnement] --> B[OpenAPI / Swagger]
    B --> C[green-api-auto-discover.py]
    C --> D[Découverte des endpoints]
    C --> E[Mesures HTTP]
    C --> F[Calcul des règles]
    D --> G[Rapport JSON]
    E --> G
    F --> G
    G --> H[Dashboard HTML]
    G --> I[Dashboard Markdown]

Le wrapper green-score-analyzer_withdiscovery.sh orchestre le lancement ; le calcul est centralisé dans green-api-auto-discover.py.

Ce qui est mesuré sur chaque endpoint

Mesures HTTP

Code HTTP, taille téléchargée, temps total et vitesse de téléchargement

Contexte d'appel

Paramètres OpenAPI, exemples de payload, Bearer token et répétitions configurées

Énergie réseau

taille / Go × kWh réseau, avec une valeur configurable

Énergie serveur

durée × puissance serveur / 3600, puis conversion en CO₂

Les mesures sont ensuite agrégées dans auto_discovery.all_measurements et discovered_endpoints.

Comment les scores sont calculés

Green API Score

Chaque règle est évaluée sur les endpoints découverts : pagination, filtrage, compression, cache, delta, range et formats binaires

Architecture

AR01 à AR05 ajoutent les signaux événementiels, proximité runtime, API unique, autoscaling et empreinte cloud

1. Score total = Somme des points validés
2. Grade = conversion du score en A+ / A / B / C / D / E
3. Score Creedengo = (1 - règles violées / règles analysées) × 100

Le score Green API et le score Creedengo restent distincts : API en fonctionnement d'un côté, qualité éco-conception du code source de l'autre
